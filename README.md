# Document Intelligence Lab

**Question.** For information extraction from complex forms, how does a
classical OCR pipeline compare with a vision-LLM route on accuracy,
error character, and cost in time, against the same ground truth?

**Headline.** On the 50 FUNSD test forms, the Gemini vision route scored field F1 0.4029 against 0.0645 for Tesseract plus rules (difference 0.3385, one pass per document, no interval computed), but it answered only 21 of the 50 documents: 29 failed and were scored as zero, 27 of them HTTP 429 rate-limit rejections.
H1 (accuracy) and H2 (classical noise floor, word error rate 0.6942)
are CONFIRMED; H3 (classical arm 5 times faster) is INCONCLUSIVE at a
median ratio of 2.08.

**Field.** ML and AI research. **Job family.** Applied AI and
document intelligence.

**Verdict.** Functional. The plan was locked before any code or run
(PREREGISTRATION.md, commit 0774bfd, tag proposal-v1), both arms ran
end to end on all 50 test documents with raw records in results/, the
tests pass in CI on Python 3.11 and 3.12, and CI regenerates RESULTS.md
and results/metrics.json unchanged from those records. Evaluated is not
met: the ML profile asks for uncertainty on every headline number,
ablations, and the baselines a reviewer would expect, and this study
has one pass per document, no ablation, and a vision arm that was
mostly rate-limited (REPORT.md, "Threats to validity").

## Reproduce

Check the results against the evidence (anywhere, no paid call, no
OCR install; downloads the public FUNSD corpus and verifies its
SHA-256):

```text
python3 -m unittest discover -s tests -v
sh scripts/fetch_funsd.sh && python3 scripts/make_results.py && git diff --exit-code RESULTS.md results/metrics.json
```

Re-run the study (machine of record only; Arm B calls the Gemini route
and spends its quota, so it is never run without the Owner's word):

```text
sh scripts/fetch_funsd.sh        # downloads FUNSD, verifies SHA-256
sh scripts/setup_tesseract.sh    # only if no system tesseract exists
python3 src/run_arms.py --arm both
python3 scripts/make_results.py  # regenerates RESULTS.md and metrics
```

The dataset is never committed. A re-run of Arm B meets the route's
rate limits again; its timings and failure counts will differ.

## Layout

Files named in the locked PREREGISTRATION.md keep their names; the
second column gives the role each plays in the portfolio standard.

| Path | Role | What it holds |
| --- | --- | --- |
| PREREGISTRATION.md | proposal | The locked protocol and pass lines (tag proposal-v1); a test fails if one byte changes |
| REPORT.md | report | Background, method, results, error character, deviations, threats, conclusion |
| RESULTS.md | results | Verdicts and the per-document table, generated by scripts/make_results.py |
| DECISIONS.md | decisions | The Tesseract install route, amendment A1, two harness corrections |
| results/ | evidence | Raw per-document records (arm_a.jsonl, arm_b.jsonl), metrics.json, run_manifest.json, the Jev claim-check spec and record |
| src/ | code | Both arms, the shared scorer, the run driver |
| scripts/ | code | Corpus fetch, Tesseract install, the results generator |
| tests/ | tests | Scorer, extraction rules, parsing, verdicts, and the standard's layout and lock checks |
| CHANGELOG.md, CITATION.cff, SECURITY.md, LICENSE | project | Change history, citation, security policy, Apache-2.0 |

Not present, and why: no experiments/ folder, because the locked
protocol puts the raw records in results/ (results/arm_a.jsonl,
results/arm_b.jsonl are the evidence); no docs/decisions/, because the
lock names DECISIONS.md; no site/, because this study has no dashboard.
